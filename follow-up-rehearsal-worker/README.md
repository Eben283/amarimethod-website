# Private synthetic capture rehearsal — source candidate

This package adds actual private Worker RPC entrypoints around the reviewed admission, capture, registry and witness modules. It is **built source, not deployed or live proof**. It does not import or relabel the frozen `offline_synthetic` / `in_process` facade. No production Worker, D1 database, existing R2 bucket, provider, customer record or message path is bound here.

## Exact proposed topology

| Role | Worker / resource | Capability |
| --- | --- | --- |
| Private caller | `amari-followup-capture-caller-rehearsal` | Named `FollowUpRehearsalCaller.invoke` RPC; validates and forwards an already-signed envelope once, with no private signing keys |
| Control | `amari-followup-capture-control-rehearsal` | Named `FollowUpRehearsalControl.invoke` RPC; fixed synthetic operation |
| Registry | `REGISTRY` / `FollowUpRehearsalRegistryV1` | SQLite Durable Object selected from the authenticated manifest scope |
| Capture and witness | `CAPTURE_BUCKET` / `amari-followup-evidence-rehearsal` | Dedicated proposed **US-jurisdiction** R2 bucket; no unrelated existing bucket reuse |
| Issuer | `amari-followup-admission-issuer-rehearsal` | Named `FollowUpRehearsalIssuer.issue` RPC; no storage or provider bindings |

The account is pinned in all three configurations. Public routes, `workers.dev`, preview URLs and observability are disabled. No cron, queue, website assets, environment override or default manifest is configured. Default HTTP entrypoints return 404. Cloudflare documents [private routing configuration and limits](https://developers.cloudflare.com/workers/wrangler/configuration/); source configuration is not live settings readback.

All three configurations and the native test harness pin compatibility date `2026-08-27`, the latest date supported by the already installed workerd runtime. The tested and proposed shipped semantics therefore match; no runtime download is required.

## Authentication and effects

Control and issuer require `REHEARSAL_MANIFEST` and `REHEARSAL_KEYS` secrets, with canonical JSON checked by `src/protocol.mjs`. The caller instead uses that same signed manifest plus public-only `REHEARSAL_CALLER_KEYS`, checked by `src/caller-authorization.mjs`; private PEM material is rejected. No real keys are included in source or generated by the preparation command. An independent owner root key signs the finite synthetic manifest. Distinct owner/operator/reader signing keys authorize fixed actions; those private keys do not belong in any of these Workers. The control receives only receipt/witness service private keys; the issuer receives only admission/capture/floor/source private keys. Public-key fingerprints are bound by the manifest and role reuse is rejected.

The permitted actions are owner `bootstrap`/`revoke`, operator `admit`/`execute`, and authenticated `status`/`result` reads. Requests carry a fresh signed nonce, exact scope and manifest digest. Control authenticates before allocating/selecting the DO and the DO authenticates again. Mutation nonces persist before action. Explicit bootstrap requires empty SQLite, DO key/value storage and the dedicated R2 bucket; constructors never install or activate anything. A partial bootstrap is not automatically retried or repaired. The sole effect is a unique synthetic counter row, not a message, payment or arbitrary callback.

The protocol bounds its manifest lifetime to one hour, request signatures to 30 seconds, retained synthetic data to at most one day from the original timestamp, and each serialized envelope to 16 KiB. Per-invocation source checks bound SQL statements, transactions, native calls and streamed bytes. Configured CPU/subrequest limits are additional provider settings, not proof of a dollar cap. A timeout stops subsequent authorized work but does **not** prove earlier native writes were cancelled or settled; an uncertain mutation needs read-only reconciliation, never an action retry. Status/result neither renew authority nor establish writer drain.

## Read-only preparation

From the repository root, using already installed dependencies:

```sh
node scripts/follow-up-rehearsal-release.mjs inspect
```

`inspect` makes no network call or persistent build output. It hashes both in-memory esbuild bundles, their actual transitive source graph, both exact configuration files, this README, the preparation script, package files and installed Node/esbuild/Miniflare/workerd versions. Its output explicitly labels the local working tree and is **not** publication, approval, runtime attestation or a deployable release. Any source/configuration/tool change changes the candidate digest. Tool versions and package-lock agreement do not independently attest the installed executable binaries.

Only after the exact source is published, reviewed and merged to main, a fresh local source check can be requested:

```sh
node scripts/follow-up-rehearsal-release.mjs prepare --reviewed-revision FULL_REVIEWED_40_HEX_SHA --reviewed-artifact REVIEWED_64_HEX_ARTIFACT_DIGEST
```

The placeholders are deliberately not executable approvals. `prepare` refuses dirty/untracked source, noncanonical origin, HEAD or cached `origin/main` unequal to the explicit reviewed revision, bytes absent from that commit, altered digest, unexpected config/bindings and a stale fresh remote main. It makes one read-only `git ls-remote` call to the fixed GitHub repository; it never fetches, commits, publishes, provisions or deploys. Source is rechecked afterward. This is a point-in-time review aid, not a durable release lock. **No deployment command exists in this script.** Wrangler is not installed by it and Wrangler upload validation is not claimed. Native tests exercise the actual source using Miniflare; release tests simulate Git replies and do not prove publication.

Focused checks (no package installation):

```sh
node node_modules/vitest/vitest.mjs run --config reminder-engine-worker/vitest.config.js reminder-engine-worker/src/follow-up-rehearsal-release.test.js
node node_modules/vitest/vitest.mjs run --config reminder-engine-worker/vitest.config.js reminder-engine-worker/src/follow-up-private-rehearsal.test.js
```

Owner verification on 2026-08-28 passed all 36 focused private-rehearsal cases (9.96 seconds), including native execution of the unwrapped exact release bundles, and all 63 release-preparation cases. This is local evidence, not live acceptance. Run native suites serially.

The observed local synthetic execute path used 104 SQL statements, four transactions, four sync calls, 13 R2 gets, five R2 puts, 26 stream reads and two remote issuer RPCs, with 17,224 counted payload bytes. Its DO-internal `nativeCalls` count was 50; adding the control-to-DO RPC makes 51 downstream calls. The source ceiling of 63 DO-internal calls reserves that additional hop within the signed 64-call downstream quota. Caller-to-control ingress is separate. These measurements describe this fixture's work, not an invoice, provider billing-unit count, worst-case estimate or proof that the path uses at most 20 SQL statements. Remaining live cost accounting must cover the whole bounded run and cleanup.

## Remaining live gates

### Guarded deployment and private calling increment

The source increment adds `scripts/follow-up-rehearsal-deploy.mjs` and a private caller. The deployment driver is a bounded first-install transport, not permission to run it. Its read-only `inspectDeploymentCandidate()` hashes the extended source graph and actual three in-memory upload bundles. `deployRehearsal()` requires explicit execution, an exact reviewed main revision and approval digest, approved secret-custody callbacks, and an independently durable one-shot `consumeRelease` authorization. An injected acknowledgement is a trusted integration contract, not proof that durable authorization exists in production. There is no deployment CLI, default credential discovery, or in-memory substitute for that authority.

The fixed transport ceiling is 112 API requests, nine attempted writes, 16 MiB aggregate transferred bytes, 1 MiB per response/upload, 15 seconds per API call and a five-minute operation authorization window, with at most eight account zones. Synchronous Git/file checks cannot be interrupted by a JavaScript timer; expiry is rechecked before any subsequent API work. The nine writes are three shell uploads, three public-URL lockdowns and three final uploads; the control upload includes its explicitly approved SQLite namespace migration. These source bounds do not establish provider billing enforcement or grant any live permissions.

Cloudflare's [script-upload metadata](https://developers.cloudflare.com/workers/configuration/multipart-upload-metadata/) does not atomically disable public URLs; [workers.dev and preview settings](https://developers.cloudflare.com/api/resources/workers/subresources/scripts/subresources/subdomain/methods/create/) are a separate operation. The proposed first-install sequence therefore explicitly includes three fixed, credential-free, binding-free, 404-only shells, disabling and reading back their public URLs, then the real issuer/control/caller uploads. A transient public 404-only URL is possible before lockdown; this is **not** an atomic private-first guarantee. Every shell, routing change and SQLite namespace migration must appear in the separately approved live manifest. Do not pass credentials or real bundles before private-settings readback succeeds.

The driver must refuse existing target Workers or namespaces, foreign resources, stale source, unexpected settings and incomplete inventories. It does not create the R2 bucket, invoke bootstrap, run the synthetic counter, retry a write, resume a partial release, roll back, or delete anything. The dedicated bucket must first have separately approved creation identity and scope. A partial or uncertain upload stops with redacted reconciliation coordinates; a timeout does not prove the upload was cancelled. Runtime secrets remain inside exact-name callback operations and must not appear in arguments, files, logs or returned reports.

The caller accepts an already-signed canonical envelope through a private service binding. It does not generate nonces, extend deadlines, sign as another role, or retry after failure. The operator/root signing host and its private ingress remain separate live integration obligations; this Worker is not a browser endpoint or a completed operator console. Caller-to-control forwarding is an additional hop outside the frozen control-to-DO/downstream budget: the observed native fixture used 52 downstream calls, and the source ceiling including the relay is 65, excluding external ingress. All 37 caller cases passed both owner and independent native runs with the exact bundled source and configured limits. This does not prove Cloudflare's billing or custom-limit enforcement; deployment and rehearsal budgets must count the whole path.

No cleanup is automatic. The live approval must identify the exact new Workers, namespace, bucket identity, fixture keys, credential owners, finite request/object/byte/time limits, budget reserve and cleanup owner. Before deletion, separately establish fencing, writer settlement and applicable restore/replay horizons. Unknown settlement is a stop condition; neither successful deployment nor read-only status is deletion authority.

Before any resource creation or live invocation, the exact source must complete independent review and publication. The deployment driver binds the reviewed revision **and its exact retained bundle bytes** to upload and readback, and refuses stale source before each write. Its Git/transport/custody tests use injected synthetic replies, not a Cloudflare account. A real host integration must still supply approved durable release authority, credential custody, dedicated bucket identity and conservative cost accounting. The older preparation bundle is not automatically the bundle Wrangler would upload, and raw Wrangler deployment is not this release path.

The owner must approve the exact new resources, existing-account create/edit permissions, private calling harness/service binding, root/caller/service secret custody and finite signed manifest. Read permissions and active subscriptions do not grant those write capabilities. The first live bootstrap must be explicit and its primary readback retained. No provider runtime behavior, durability, recoverability, source identity or actual Staff evidence is established by local tests.

The approved temporary-test spending ceiling is **USD10 aggregate incremental**, including metadata/management calls, requests, storage, billing-unit rounding and cleanup. Existing Workers Paid and R2 subscriptions avoid a new subscription requirement; they do not prove unused allowance or free usage. Successful R2 bucket inventory may be metered; actual incremental charges remain unmeasured. Source caps are not an enforceable account-wide billing cap. A bounded request/object/byte/run manifest and conservative accounting are required before the live test, with enough remaining budget for cleanup.

This package exposes no deletion, reset, unlock, retry, restoration or migration replay method. The later cleanup plan must fence admission, establish native writer settlement/drain and restore/replay horizons, then remove only the newly created manifest-listed fixtures/resources and ephemeral credentials under explicit authority. Unknown settlement is a stop condition, not permission to delete. Retention deadlines here restrict access; they do not physically erase the original R2/DO copies or prove all-copy deletion.

The broader CRM production integration, real event/subject/parent identity, original-copy retention, independent restore custody and Staff coverage remain open. The original lost operational payload is not recovered. Coherent rollback of all participating stores/issuer authority can remain undetectable; exactly-once execution is not claimed.
